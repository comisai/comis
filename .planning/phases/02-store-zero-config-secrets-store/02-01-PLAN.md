<objective>
Close the `MasterKeyWriteResult.keyHex` type gap — the keystone of STORE-01.

Purpose: `writeMasterKeyIfAbsent` currently computes `keyHex` internally at line 61 but
discards it (`return { written: true, path: envPath }`). The daemon cannot use the
freshly-written key in the same boot without a restart because `keyHex` is never surfaced.
Adding `keyHex?: string` to the return type (defined iff `written === true`) enables same-boot
store initialization via the `seedKeyHex` threading in Plan 03.

Output:
- Widened `MasterKeyWriteResult` interface with `readonly keyHex?: string`
- `writeMasterKeyIfAbsent` returns `keyHex` on the write path; does NOT return it on the
  already-present path
- RED test (commits first, MUST fail on pre-patch): asserts `result.keyHex` matches
  `/^[0-9a-f]{64}$/` — fails because pre-patch code returns `keyHex: undefined`
- GREEN tests (after patch): full coverage of both write and idempotent paths
</objective>
