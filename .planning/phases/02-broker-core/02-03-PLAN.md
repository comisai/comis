Proxy CONNECT client (inline helper in test file):
```typescript
// Manual TCP CONNECT client — no third-party dependency
async function connectThroughProxy(
  brokerPort: number,
  proxyToken: string,
  targetHostPort: string,   // e.g. "api.anthropic.com:443" — what we send to the broker
): Promise<{ statusCode: number; socket: net.Socket }> {
  return new Promise((resolve, reject) => {
    const socket = net.connect(brokerPort, "127.0.0.1", () => {
      const connectLine =
        `CONNECT ${targetHostPort} HTTP/1.1\r\n` +
        `Host: ${targetHostPort}\r\n` +
        `Proxy-Authorization: Bearer ${proxyToken}\r\n` +
        `\r\n`;
      socket.write(connectLine);
    });
    let buf = "";
    socket.on("data", (chunk) => {
      buf += chunk.toString("latin1");
      const idx = buf.indexOf("\r\n\r\n");
      if (idx === -1) return;
      const statusLine = buf.slice(0, buf.indexOf("\r\n"));
      const statusCode = parseInt(statusLine.split(" ")[1] ?? "0", 10);
      resolve({ statusCode, socket });
    });
    socket.on("error", reject);
    setTimeout(() => reject(new Error("connect timeout")), 3000);
  });
}
```

IMPORTANT — HTTP/1.1 header parsing inside the tunnel:
After responding "200 Connection established", the broker reads the client socket for the real HTTP request. Parse ONLY the header section (read until \r\n\r\n), enforce a size cap (8 KB), fail closed on parse error → destroy socket + emit broker:denied. Extract: method, URL path, headers. Apply resolveBinding + pathAllowed + secretManager.get + applyInjections, then net.connect to the real upstream (the loopback fixture port during tests), write the modified HTTP request, and pipe the response back.

IMPORTANT — upstream in tests is a plain HTTP server, not HTTPS. In the test fixture, the "target" in the CONNECT is actually a plain HTTP server on a random loopback port. The broker does NOT check whether the upstream is HTTPS or not — it connects via net.connect regardless. This is correct for Phase 2 (TLS termination is Phase 3).

CONNECT handler pipeline (strict ordering — no upstream socket created until all gates pass):

Step 1 — Validate Proxy-Authorization:
```
const auth = req.headers["proxy-authorization"];
if (!auth?.startsWith("Bearer ")) {
  // write 407, emit broker:denied(reason:"bad_token"), destroy, return
}
const rawToken = auth.slice(7);
const session = deps.sessionManager.consumeToken(rawToken);
if (!session) {
  // write 407, emit broker:denied(reason:"bad_token"), destroy, return
}
```

Step 2 — Parse and normalize host:
```
const authority = req.url ?? "";
const host = normalizeHost(authority);
```

Step 3 — Read HTTP request from tunnel socket (AFTER sending 200):
- Respond: `clientSocket.write("HTTP/1.1 200 Connection established\r\n\r\n");`
- Then read until \r\n\r\n with 8 KB cap — fail closed on parse error
- Parse method, path, headers from the header section

Step 4 — Resolve binding:
```
const resolved = resolveBinding(deps.bindings, host, path);
if (!resolved) {
  // write 403 to clientSocket (tunnel already open — destroy tunnel), emit broker:denied(reason:"no_binding"), return
}
if (!pathAllowed(resolved.rule, path)) {
  // write 403, emit broker:denied(reason:"path_policy"), return
}
```

IMPORTANT ordering for fail-closed: binding resolution happens BEFORE emitting 200 OR after? The answer from the design: auth gate (407) happens on the CONNECT request before any 200. Binding + secret resolution ALSO should happen before forwarding — but we need the HTTP request (path) for pathAllowed, which only arrives after 200. Therefore: send 200 to establish the tunnel, read the first HTTP request headers, then gate on binding+secret. If any gate fails, destroy the clientSocket (tunnel) — no upstream is connected.

Step 5 — Resolve secret (BEFORE net.connect):
```
const secretValue = deps.secretManager.get(resolved.binding.secretRef);
deps.eventBus.emit("secret:accessed", {
  secretName: resolved.binding.secretRef,
  agentId: session.agentId,
  outcome: secretValue !== undefined ? "success" : "not_found",
  timestamp: deps.clock.now(),
});
if (secretValue === undefined) {
  // emit broker:credential_unavailable, destroy clientSocket, return
  // ZERO net.connect calls at this point
}
```

Step 6 — Inject + forward (only reached when ALL gates pass):
```
// Build mutable headers from parsed headers
// Call applyInjections(resolved.rule.inject, { headers, url, secret: secretValue })
// emit broker:injected (ruleKind from the rule, NOT the secret)
// THEN net.connect(host, port) — this is the FIRST upstream socket
// Write the modified HTTP request to upstream
// pipe upstream response back to clientSocket
```

Logger child: `const log = deps.logger.child({ submodule: "mitm-broker" });`
Every pipeline stage logs at debug with `step:` tag. Every error logs with `hint:`, `errorKind:`, and `err:` (not `error:`).

NO Date.now() — all `deps.clock.now()`.
NO raw throw — use clientSocket.destroy() for all error paths.
`sessionId: "unknown"` for 407 before the session is resolved (event requires string).

Header size cap: if more than 8192 bytes received before \r\n\r\n, destroy socket (request smuggling prevention).
