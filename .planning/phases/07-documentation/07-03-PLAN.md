**reference/secret-manager.mdx:**
Read the file. Find the section about consumers of SecretManager (or about how secrets are resolved/used). Add a subsection or paragraph "### Credential Broker":

The credential broker is a per-request consumer of SecretManager. On each proxied request, the broker calls `SecretManager.get(secretRef)` to resolve the binding's secret. It is never cached to disk — the key lives only in the daemon's encrypted store and in memory for the duration of the injection.

Resolution emits a `secret:accessed` audit event with fields: `secretName`, `agentId`, `outcome` (success/not_found), `timestamp`. A `not_found` outcome causes the broker to return 502 and never forward the request.

Scoping: the broker uses the platform (unscoped) SecretManager for executor-level bindings. Per-agent scoped secrets (`secretRefs` in exec tools) use the ScopedSecretManager — these are two separate injection paths. [See Credential Broker →](/security/credential-broker)

**Network modes (`SandboxOptions.network`):**

| Mode | Value | bwrap args | Description |
|------|-------|-----------|-------------|
| Open (default) | `{ mode: "open" }` or `undefined` | `--unshare-all --share-net` | Full network access; standard exec sandbox |
| Broker-only | `{ mode: "broker-only", brokerSocketPath: "..." }` | `--unshare-all --unshare-net --bind <path> <path>` | Driven-CLI sandbox; only the broker unix socket reachable via bind-mount (Linux only) |

**Secure credential home (`secureCredentialHome: boolean`):**

When `true`, the following mounts are omitted from the sandbox so credential files are unreachable:
- `~/.claude` (RW bind removed)
- `~/.claude.json` (RO bind removed)
- `~/.local/share/claude` (RW bind removed)

The `broker-only` network mode and `secureCredentialHome` are set automatically for driven-CLI spawns — they are not operator-configurable directly. [Credential Broker →](/security/credential-broker)
