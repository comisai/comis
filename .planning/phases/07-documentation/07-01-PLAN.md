- broker:session_opened — sessionId, agentId, host, presetId?, timestamp
- broker:session_closed — sessionId, agentId, durationMs, reason (teardown/error), timestamp
- broker:request — sessionId, host, path, method, timestamp
- broker:injected — sessionId, host, ruleKind, timestamp

## The Problem
Explain: exec tools can read env, cat, /proc — so handing a secret to an agent process exposes it. The broker solves this by keeping the key in the daemon and injecting at the network boundary.

## Architecture
Include the conceptual flow (not ASCII art, plain numbered flow):
1. Store key once: `secrets_manage set ANTHROPIC_EXECUTOR_KEY`
2. Enable binding: config entry maps api.anthropic.com → inject x-api-key
3. Agent runs CLI: sandbox sees only ANTHROPIC_API_KEY=broker-placeholder + broker CA (NODE_EXTRA_CA_CERTS)
4. Broker intercepts: terminates TLS with own CA, matches against binding, swaps placeholder → real secret for allow-listed hosts
5. Audit: every inject/deny/blocked-egress event carries agentId + traceId

Note the broker-vs-secretRefs distinction (from design §3.3): secretRefs injects env vars scoped to exec tools (good for simple cases); the broker is for driven API-key CLIs where the process itself must not hold the key.

## Secure credential home

When `secureCredentialHome: true` is set on the sandbox, the following mounts are removed for the credentialed sandbox:
- `~/.claude` (RW bind)
- `~/.claude.json` (RO bind)
- `~/.local/share/claude` (RW bind)

This means `cat ~/.claude/.credentials.json` inside the sandbox returns "no such file".

## Network isolation (Linux)

<!-- publish gate: flip to full containment claims post-R1 -->

On Linux, the credentialed sandbox runs with `--unshare-net`; the broker unix socket is the only bind-mounted network path — making the broker the designed-to-be-only destination for driven-CLI traffic. Validation of this kernel-enforcement on the Linux production host class is in progress (R1 gate).

Network modes (`SandboxOptions.network`):
| Mode | bwrap args | Description |
|------|-----------|-------------|
| `open` (default) | `--unshare-all --share-net` | Standard exec sandbox; full network access |
| `broker-only` | `--unshare-all --unshare-net --bind <socketPath> <socketPath>` | Driven-CLI sandbox; only the broker unix socket is reachable |

macOS note: broker-only network mode requires bubblewrap and is Linux-only. The broker still runs on macOS (TLS termination, injection, events) but without network namespace enforcement.

<Info>Source: packages/skills/src/tools/builtin/sandbox/bwrap-provider.ts (broker-only branch at line 234)</Info>

## Broker vs exec secretRefs

Two injection paths exist:

| | exec secretRefs | Credential broker |
|---|---|---|
| **What it does** | Injects env vars scoped to the exec tool | Injects credentials at the network boundary |
| **Who holds the secret** | The exec process (env var visible inside) | The daemon only (placeholder in sandbox) |
| **Use when** | Simple scripts needing a key as env var | API-key CLIs (Claude Code, curl, etc.) |
| **Network guard** | None | Broker-only egress (Linux) |

Use `secretRefs` for simple key-as-env-var cases. Use the credential broker when you need the key to be unreachable inside the sandbox.

## Troubleshooting

**Broker request fails with 407:**
```bash
# Check broker events in logs
grep 'broker:denied' ~/.comis/logs/daemon.log | grep bad_token
# Cause: session token missing or expired (single-use; new token per driven-CLI spawn)
```

**Broker returns 403 no_binding:**
The requested host has no matching binding. Add a `hostRules` entry or use a preset.

**Broker returns 502:**
SecretManager returned undefined for the `secretRef`. Verify: `comis secrets list` shows the key.

**Broker returns 501 (WebSocket):**
WebSocket credential injection is not supported (WS-01 is a future capability). The broker returns 501 with a `ws_upgrade_not_supported` reason so the error is actionable rather than a silent hang.

**Step-tag grep:**
Every broker log entry carries a `step` field. To trace a full request:
```bash
grep '"traceId":"<your-trace-id>"' ~/.comis/logs/daemon.log | jq '{step, event}'
```
