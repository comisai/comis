Comis is most useful when an agent system has moved beyond an experiment and
needs explicit authority, recoverable state, bounded cost, and evidence. The
patterns below use capabilities available in the runtime today; they are not
claims of turnkey industry solutions.

## Governed research and analysis

**What you build:** parallel agents gather sources, a synthesis step reconciles
them, and a critic checks the result before delivery.

**Why Comis fits:**

- [execution graphs](/agents/execution-graphs) coordinate parallel research,
  barriers, synthesis, criticism, and retries;
- [context recovery](/agents/context-management) lets the run search and expand
  canonical detail omitted from the active prompt;
- [memory provenance](/agents/memory) keeps learned claims tied to sources and
  trust signals;
- configured [budgets and cost controls](/agents/safety) bound the run; and
- [traces and incident evidence](/operations/observability) make the result
  reviewable.

This is the recommended first multi-agent workflow because it demonstrates the
governance model without requiring broad production permissions.

## Controlled operational investigation

**What you build:** agents collect read-only system evidence, correlate events,
and produce an incident report with cost and audit records.

**Why Comis fits:**

- scheduled checks and [heartbeats](/agent-tools/scheduling) can trigger bounded
  investigations;
- scoped [tools and capability gates](/security/capability-model) limit which
  operational surfaces an agent can reach;
- [incident explanation](/operations/incident-bundle) connects execution,
  delivery, policy, and cost evidence; and
- supported [approval paths](/security/approvals) can pause configured
  privileged actions.

Keep the first deployment read-only. Add remediation only after approval
behavior and Linux execution isolation are enabled and tested on the target
host.

## Routed support and knowledge operations

**What you build:** specialized agents handle different channels, users, or
knowledge domains while the operator keeps one control model.

**Why Comis fits:**

- [routing bindings](/agents/routing) choose the agent for each inbound path;
- each agent can have separate context, memory, tools, budgets, secret rules,
  and workspace files;
- [RAG memory](/agents/rag) retrieves relevant knowledge with trust-aware
  ranking; and
- delivery and fleet diagnostics expose failures across channels.

Human escalation and destructive actions still need application-specific
workflow design. Comis approval support is not yet a universal policy engine.

## When a smaller tool may be enough

If you need one personal assistant, a model wrapper, or only a graph library,
a smaller tool may be simpler. Choose Comis when several persistent agents,
credentials, memories, budgets, interfaces, and operators need one inspectable
governance model.
